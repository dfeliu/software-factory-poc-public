# incidents-api

Benchmark API for incident management, built from the `fastapi-service` Golden
Path.

Owner: Software Factory POC.

## Local use

```bash
cp .env.example .env
uv sync --locked --all-groups
uv run uvicorn application.main:app --reload
```

`GET /health` is a liveness endpoint; it does not check PostgreSQL.

## API

The API is available at `/docs`. It exposes `POST`, `GET`, `PATCH` and `DELETE`
operations for `/incidents`.

- `status`: `OPEN`, `IN_PROGRESS`, `RESOLVED`, `CLOSED`.
- `priority`: `LOW`, `MEDIUM`, `HIGH`.
- `DELETE /incidents/{id}` is a soft delete: it sets `deleted_at`; deleted
  incidents are excluded from list, get and update operations.
- `GET /incidents` has a stable ascending `id` order. Filters and pagination
  are intentionally deferred.

For Docker Compose:

```bash
cp .env.example .env
docker compose up -d db
docker compose run --rm migrate
docker compose up -d app
```

The example values are local placeholders. Do not commit `.env` or put a real
secret in it.

## Configuration

For local Compose, `POSTGRES_DB`, `POSTGRES_USER`, and `POSTGRES_PASSWORD` are
the base database values. The application builds its URL from them. In another
environment, injected `DATABASE_URL` takes precedence.

## CI

The authoritative repository workflow in `.forgejo/workflows/ci.yml` validates
unit tests, PostgreSQL 18 integration tests and migrations, Ruff, the Docker
build, locked dependencies and the runtime image. It does not deploy or publish
an image. Files under `.github/workflows/` are retained only as legacy adapters
for the passive mirror and are not the authoritative CI contract.

The dependency audit uses the project's reproducible lockfile without adding
the audit tool to this project:

```bash
uv export --locked --all-groups --no-emit-project --output-file /tmp/incidents-api-requirements.txt
uvx --from pip-audit==2.10.1 pip-audit -r /tmp/incidents-api-requirements.txt
docker build --target runtime --tag incidents-api:ci-local .
```

## Migrations

```bash
uv run --locked alembic heads
uv run --locked alembic upgrade head
uv run --locked alembic revision --autogenerate -m "describe change"
```

Review autogenerated revisions. Migrations never run during application startup.

The initial migration creates `incidents`, including `deleted_at` for soft delete.
