# Factory run record

## Purpose

Each factory execution must have one `factory_run_id` and preserve the base measurements required for comparable POC results. This document defines the logical record only; it does not select storage, transport or instrumentation.

## Field contract

| Field | Description | Logical type | Unit | Required | N/A condition | Intended source |
|---|---|---|---|---|---|---|
| `factory_run_id` | Stable identifier for one factory execution. | string | identifier | Yes | Never | Factory runtime or execution coordinator. |
| `scenario` | Benchmark scenario being executed. | string | scenario identifier | Yes | Never | Benchmark scenario definition. |
| `architecture` | Architecture or variant under evaluation. | string | architecture identifier | Yes | Never | Benchmark execution configuration. |
| `project` | Project subjected to the run. | string | project identifier | Yes | Never | Benchmark execution configuration. |
| `started_at` | Start time of the execution. | timestamp | UTC date-time | Yes | Never | Factory runtime or execution coordinator. |
| `finished_at` | End time of the execution. | timestamp | UTC date-time | Yes when finished | Run is still in progress or was not started. | Factory runtime or execution coordinator. |
| `duration` | Elapsed execution time. | duration | seconds | Yes when finished | Run is still in progress or lacks valid timestamps. | Derived from runtime timestamps. |
| `success` | Whether the run reached its declared successful terminal condition. | boolean | true/false | Yes when finished | Run is still in progress. | Factory runtime and validation outcome. |
| `failure_reason` | Concise cause when the run is unsuccessful. | string | text | Yes when `success` is false | `success` is true or run is in progress. | Runtime, validation or reviewer evidence. |
| `retries` | Number of retry attempts after the initial attempt. | integer | attempts | Yes when finished | Run is still in progress. | Factory runtime or execution coordinator. |
| `human_interventions` | Count of distinct human interventions needed during the run. | integer | interventions | Yes when finished | Run is still in progress. | Execution log or benchmark operator record. |
| `human_minutes` | Human effort attributable to the run. | decimal | minutes | Yes when finished | Run is still in progress or effort was not measured. | Benchmark operator record. |
| `model` | Model used for reasoning, if any. | string | model identifier | Yes | The run has no model-assisted step. | Model invocation record. |
| `input_tokens` | Input tokens consumed by the model. | integer | tokens | Yes when model data is available | No model-assisted step or provider does not report it. | Model usage record. |
| `cached_tokens` | Input tokens served from cache. | integer | tokens | Yes when model data is available | No model-assisted step or provider does not report it. | Model usage record. |
| `output_tokens` | Output tokens generated by the model. | integer | tokens | Yes when model data is available | No model-assisted step or provider does not report it. | Model usage record. |
| `llm_cost` | Cost attributable to model usage. | decimal | source-currency amount | Yes when model cost is available | No model-assisted step or provider does not report cost. | Model usage or billing record. |
| `github_action_minutes` | CI execution time billed or measured by GitHub Actions. | decimal | minutes | Yes when applicable | The run does not use GitHub Actions or the value is unavailable. | CI usage record. |
| `cloudflare_requests` | Cloudflare requests attributable to the run. | integer | requests | Yes when applicable | The run does not use Cloudflare or the value is unavailable. | Cloudflare usage record. |
| `cloudflare_cpu_ms` | Cloudflare CPU time attributable to the run. | integer | milliseconds | Yes when applicable | The run does not use Cloudflare or the value is unavailable. | Cloudflare usage record. |
| `workflow_steps` | Workflow steps executed for the run. | integer | steps | Yes when applicable | The architecture has no workflow engine or the value is unavailable. | Factory workflow execution record. |
| `sandbox_seconds` | Sandbox execution time attributable to the run. | decimal | seconds | Yes when applicable | The run does not use a sandbox or the value is unavailable. | Sandbox execution record. |
| `platform_cost` | Non-LLM platform cost attributable to the run. | decimal | source-currency amount | Yes when available | The cost is not measurable or no platform cost applies. | Platform usage or billing record. |
| `tests_passed` | Result of the applicable test validation. | boolean | true/false | Yes when tests are run | Tests are not applicable or the run ended before test execution. | Test execution record. |
| `lint_passed` | Result of the applicable lint validation. | boolean | true/false | Yes when lint is run | Lint is not applicable or the run ended before lint execution. | Lint execution record. |
| `dependency_audit_passed` | Result of the required dependency-audit control. It is independent of image scanning. | boolean | true/false | Yes when dependency auditing is applicable | The control is explicitly N/A under its declared scope. Missing, invalid or unexecuted required evidence is `false`. | Dependency-audit control envelope and raw report. |
| `image_scanner_passed` | Raw image-scanner result under the configured HIGH/CRITICAL threshold. It does not consider exceptions. | boolean | true/false | Yes when image scanning is applicable | The control is explicitly N/A under its declared scope. Missing or invalid evidence is `false` at the aggregate boundary. | Image scanner report and image-control envelope. |
| `image_security_gate_passed` | Result of applying ADR-004 to raw image findings and active applicable exceptions. | boolean | true/false | Yes when image vulnerability validation is applicable | The control is explicitly N/A under its declared scope. Missing or invalid evidence is `false` at the aggregate boundary. | Image gate evidence and raw scanner report. |
| `security_passed` | Aggregate security result: every required applicable control must pass. Initially, `dependency_audit_passed AND image_security_gate_passed`. It is fail-closed for missing, invalid or unexecuted required evidence. | boolean | true/false | Yes when any required security control is configured | No required security control is applicable. | Explicit security-summary evidence. |
| `image_security_findings_total` | Total image-vulnerability findings emitted in the raw report within its configured scope. | integer | findings | Yes when image scanning produces a usable report | Image scanning is N/A or no usable report exists. | Raw image scanner report. |
| `image_security_findings_high` | HIGH-severity image-vulnerability findings. | integer | findings | Yes when image scanning produces a usable report | Image scanning is N/A or no usable report exists. | Raw image scanner report. |
| `image_security_findings_critical` | CRITICAL-severity image-vulnerability findings. | integer | findings | Yes when image scanning produces a usable report | Image scanning is N/A or no usable report exists. | Raw image scanner report. |
| `image_security_findings_fixable` | Image findings for which the evidence identifies a concrete, verifiable remediation. | integer | findings | Yes when image scanning produces a usable report | Image scanning is N/A or no usable report exists. | Raw image scanner report and remediation classification. |
| `image_security_findings_unfixed` | Image findings for which evidence explicitly identifies no currently published remediation. | integer | findings | Yes when image scanning produces a usable report | Image scanning is N/A or no usable report exists. | Raw image scanner report and remediation classification. |
| `image_security_findings_fix_status_unknown` | Image findings whose remediation status cannot safely be classified from available evidence. | integer | findings | Yes when image scanning produces a usable report | Image scanning is N/A or no usable report exists. | Raw image scanner report and remediation classification. |
| `active_image_security_exceptions` | Stable identifiers of active, applicable image-vulnerability exceptions used in the gate evaluation. | array of strings | exception identifiers | Yes when image vulnerability validation is evaluated | Image scanning is N/A or no gate evaluation occurs. | Versioned exception records and image gate evidence. |
| `active_image_security_exceptions_count` | Number of identifiers in `active_image_security_exceptions`. | integer | exceptions | Yes when image vulnerability validation is evaluated | Image scanning is N/A or no gate evaluation occurs. | Derived from `active_image_security_exceptions`. |
| `scanner_passed` | **Deprecated alias** of `image_scanner_passed`. | boolean | true/false | Only while compatibility is required | See canonical field. | Image control evidence. |
| `security_gate_passed` | **Deprecated alias** of `image_security_gate_passed`; it is not the aggregate security result. | boolean | true/false | Only while compatibility is required | See canonical field. | Image gate evidence. |
| `security_findings_*` | **Deprecated aliases** of the corresponding `image_security_findings_*` fields. | integer | findings | Only while compatibility is required | See canonical fields. | Image scanner report. |
| `active_security_exceptions` / `active_security_exceptions_count` | **Deprecated aliases** of the corresponding `active_image_security_exceptions` fields. | array / integer | exception identifiers / exceptions | Only while compatibility is required | See canonical fields. | Image gate evidence. |
| `governance_level` | Governance level applied to the run: `G0`, `G1` or experimental `G2`. | string | level identifier | Yes | Never. | POC execution configuration. |
| `risk_class` | Classified risk category when a governance level evaluates risk. | string | category | Yes when risk classification applies | G0 and G1 do not classify risk for authorization. | Policy evaluation evidence. |
| `policy_decision` | Policy outcome relevant to merge eligibility. | string | decision identifier | Yes when a PR is evaluated for merge | No PR or merge evaluation occurred. | Deterministic policy evidence. |
| `merge_mode` | How the PR was merged or intended to be merged: `human`, `automatic`, or `none`. | string | mode identifier | Yes when a PR is created | No PR step occurred. | Pull-request or executor record. |
| `human_approval_result` | Whether the required human approval was valid for the exact proposed head commit. | boolean | true/false | Yes when G1 evaluates a PR | G0 or no PR evaluation. | Pull-request review record. |
| `merge_eligibility_result` | Result of fail-closed merge eligibility. | string | `eligible` / `blocked` / `needs_human` | Yes when G1 or G2 evaluates a PR | G0 or no PR evaluation. | Policy evidence. |
| `merge_actor` | Identity that executed the merge, if one occurred. | string | actor identifier | Yes when a merge occurred | No merge occurred. | SCM audit record. |
| `pr_created` | Whether a pull request was created for the change. | boolean | true/false | Yes when the PR step is reached | The scenario or run does not include a PR step. | Repository or pull-request record. |
| `pr_accepted` | Whether the created pull request received the defined human acceptance. | boolean | true/false | Yes when a PR is created and reviewed | No PR was created, it is not reviewed, or the scenario has no PR step. | Human review or pull-request record. |
| `deployment_success` | Result of an attempted deployment for the change. | boolean | true/false | Yes when deployment is attempted | No deployment was attempted or the scenario has no deployment step. | Deployment execution and health evidence. |

## G2 extension

The following fields are required when `governance_level = G2`:

| Field | Meaning |
|---|---|
| `change_id` | Stable objective identifier shared by all attempts and the single PR. |
| `attempt_count` | Total Builder attempts, including the initial attempt. |
| `governance_profile` / `enforcement_mode` | Exact profile and `shadow` or `enforced` activation. |
| `risk_class_source` / `risk_signals` | Deterministic classifier source and ordered reason signals. |
| `review_head_commit` / `review_prompt_version` | Exact reviewed head and versioned Reviewer contract. |
| `agent_review_duration` / `policy_evaluation_duration` | Review and policy time in seconds. |
| `policy_id` / `policy_revision` / `policy_sha256` / `policy_source_commit` | Reproducible policy identity, content and executing code revision. |
| `evaluation_bundle_hash` / `objective_hash` / `review_report_hash` | Hash bindings that make the decision reproducible without storing private reasoning. |
| `policy_reason_codes` | Ordered machine-readable reasons for the decision. |
| `time_waiting_for_human` | Queue time caused by a required escalation, in seconds. |
| `human_override` | Whether a person changed the normal policy outcome. |
| `sampled_human_audit_result` | `pass`, `fail` or `N/A` for HOTL sampling. |
| `post_merge_regression` / `rollback_required` | Observed post-merge safety outcomes. |
| `kill_switch_scope` / `kill_switch_state` | Repository/global scope and observed pause state. |
| `projection_lag_seconds` | Delay between immutable event and PostgreSQL projection. |

## Agentic candidate extension

When the bounded Builder/Reviewer loop is used, retain these non-secret
references in addition to the applicable G2 fields. They are evidence only and
do not authorize a publication or merge.

| Field | Meaning |
|---|---|
| `candidate_id` / `candidate_patch_sha256` | Immutable identity of the exact local patch and its digest. |
| `candidate_binding_ref` / `bound_head_sha` | Reference to the deterministic exact-diff binding and the resulting remote head, when publication is in scope. |
| `agentic_routing_policy_id` / `agentic_routing_policy_version` / `agentic_routing_policy_sha256` | Frozen routing policy selected at the start of the change. |
| `builder_result` / `candidate_review_result` / `validation_result` | Bounded outcomes of Builder, independent Reviewer and deterministic validation. |

## Recording rules

- `false`, `0` and `N/A` have different meanings and must not be substituted for one another.
- Monetary values retain their source currency; any normalization required for comparison is deferred to the benchmark protocol.
- A record must retain the evidence source or reference needed to audit a reported value when that integration exists.
- `image_security_findings_fixable + image_security_findings_unfixed + image_security_findings_fix_status_unknown` must equal `image_security_findings_total` when a usable image scanner report exists.
- `active_image_security_exceptions_count` must equal the number of distinct identifiers in `active_image_security_exceptions`.
- `image_scanner_passed = false` and `image_security_gate_passed = true` is valid only when active, applicable exceptions are recorded; it never changes raw image evidence.
- `security_passed` is evaluated only at the explicit aggregation boundary. It must be `false` if a required control has missing, invalid, failed or unexecuted evidence.
- In G1, `human_approval_result = true` and `merge_eligibility_result = eligible` must refer to the same PR and head commit. An automatic merge without both values is invalid benchmark evidence.
- In G2, the objective, Reviewer report, policy decision, executor observation and merge event must bind the same `change_id`, PR, repository and `head_sha`. A new head invalidates every earlier review and decision.
- PostgreSQL is a replayable read model. Missing projection data never changes the authoritative immutable event or permits a merge.
- Deprecated aliases must equal their canonical `image_*` values. They may be removed only after the benchmark record schema is versioned or migrated and every active Factory Core consumer uses the canonical fields; they must not become a second permanent contract.
- The record contains raw run data; derived calculations belong in `derived-metrics.md`.
